# Tyman

Стартовий 3D-проєкт на **Godot 4.7.2** із GDScript, тестовою ігровою сценою,
автоматичними збірками Windows/Linux і підготовкою релізних кандидатів.
Використовується рендерер **GL Compatibility**; зовнішні графічні ресурси не потрібні.

Можливості гри й автоматизації додано в [PR #2](https://github.com/qwer605/tyman/pull/2).
Повний опис реалізованого функціоналу: [Можливості проєкту](docs/features.md).

## Швидкий запуск

1. Установіть Godot **4.7.2** — версію зафіксовано в [`.godot-version`](.godot-version).
2. Імпортуйте файл [`project.godot`](project.godot) через менеджер проєктів Godot.
3. Відкрийте проєкт і натисніть **F5**.
4. Рухайтеся майданчиком, стрибайте на платформи та зберіть усі п'ять кристалів.

Для запуску гри Node.js не потрібен. Він використовується для релізної автоматики
та її тестів; у CI встановлюється **Node.js 24**.

| Клавіша або дія | Призначення |
| --- | --- |
| Фізичні клавіші W, A, S, D | Рух відносно напрямку камери |
| Рух мишею | Поворот камери |
| Space | Стрибок із поверхні |
| R | Повернення персонажа на старт |
| Esc | Звільнення вказівника миші |
| Клік у вікні гри | Повторне захоплення вказівника |

Рахунок зібраних кристалів показано на екрані. Повернення на старт не скидає його;
для нового проходження запустіть сцену знову.

## Перевірки й збірки

У середовищі, де Godot доступний як команда `godot`:

```sh
npm ci --prefix .github/release --ignore-scripts
npm test --prefix .github/release
godot --headless --editor --path . --import
godot --headless --path . --script tests/smoke.gd
```

Приклади для PowerShell із повним шляхом до Godot та команди експорту наведено
в [посібнику з розробки](docs/development.md).

CI запускається для PR у `main` і `release/*`, а також після змін у `main`.
Він перевіряє релізну логіку й ігрові механіки, експортує Windows/Linux та перевіряє
запуск Linux-збірки. Готові архіви зберігаються **14 днів** у
**Actions → CI → потрібний запуск → Artifacts**.

## Як випустити зібрані зміни

1. Об'єднайте потрібні задачі в `main` через PR. Обов’язкове схвалення іншим учасником не вимагається.
2. Відкрийте **Actions → Releases → Run workflow**; виберіть `main` і дію `prepare`.
3. Workflow розрахує версію, створить `release/X.Y.Z` і опублікує збірку `vX.Y.Z-rc.1`.
4. Перевірте RC. Виправлення додавайте через PR у відповідну релізну гілку —
   після злиття автоматично з'являтимуться наступні RC.
5. Для перевіреного кандидата запустіть `publish-stable`, укажіть його точний тег
   і підтвердьте `confirm_tested`. Stable отримає ті самі файли без повторної збірки.

Ручні релізні операції дозволено виконувати `qwer605` та `alx1115`.
Зміни в `main` самі по собі не публікують реліз.
Деталі та правила доступу: [Релізний процес](docs/releases.md).
